## Migrations

**Migration 1 — `user`** (`prisma/migrations/<timestamp>_user/migration.sql`): creates table `User` with the eight columns and unique indexes on `clerkId`, `email`. Generated by `prisma migrate dev --name user` against a Neon dev branch. **Requires separate owner authorization** at Gate 6 (ai-workflow-rules). Migration ownership across packages (Gate 4): F02 owns the Prisma 7 setup (`prisma.config.ts`, `lib/prisma.ts`, generator) and migration 1 (`user`); F03 owns migration 2 (`projects_and_members`) and only verifies the setup; F17 owns migration 3 (`task_run`); F18 owns migration 4 (`project_spec`). Each requires its own authorization.

External prerequisites (owner-performed, each separately authorized, none executed by this feature):
1. Neon project + dev branch; `DATABASE_URL` (pooled) and `DATABASE_URL_UNPOOLED` (direct) in `.env.local`; a test branch for `DATABASE_URL_TEST`.
2. Clerk application (dev instance): Email+Password enabled; "require email" on; publishable/secret keys; webhook endpoint for `user.created|updated|deleted` with its signing secret; two test users (A, B).
3. For local webhook delivery: a tunnel (e.g. `ngrok`) URL registered in Clerk — dev convenience only; L2 tests do not need it.
