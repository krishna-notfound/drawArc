# F03 — Design

## Architecture and components

Position: `lib/` layer (access, prisma, projects) plus one `app/**/actions.ts` file. Nothing in `components/`. Dependency direction holds: `app/editor/actions.ts → lib/projects/service.ts → lib/access.ts, lib/prisma.ts, lib/projects/externals.ts → SDKs`.

## Domain model and TypeScript contracts

Prisma additions (names and fields per `domain-model.md`; only representation details are fixed here):

```prisma
enum ProjectStatus { ACTIVE ARCHIVED }
enum MemberRole    { EDITOR VIEWER }

model Project {
  id                  String        @id @default(cuid())
  ownerId             String
  owner               User          @relation("OwnedProjects", fields: [ownerId], references: [id])
  name                String        @default("Untitled Project") @db.VarChar(100)
  description         String?       @db.VarChar(500)
  status              ProjectStatus @default(ACTIVE)
  canvasBlobPath      String?
  canvasSchemaVersion Int?
  canvasSavedAt       DateTime?
  createdAt           DateTime      @default(now())
  updatedAt           DateTime      @updatedAt
  members             ProjectMember[]
  @@index([ownerId, createdAt])
  @@index([status])
}

model ProjectMember {
  id          String     @id @default(cuid())
  projectId   String
  project     Project    @relation(fields: [projectId], references: [id], onDelete: Cascade)
  email       String                               // stored lowercase (F12 normalises)
  userId      String?
  user        User?      @relation("Memberships", fields: [userId], references: [id], onDelete: SetNull)
  role        MemberRole
  invitedById String
  invitedBy   User       @relation("SentInvites", fields: [invitedById], references: [id])
  invitedAt   DateTime   @default(now())
  acceptedAt  DateTime?
  @@unique([projectId, email])
  @@index([email])
  @@index([userId])
  @@index([projectId, role])
}
// User gains: ownedProjects Project[] @relation("OwnedProjects"), memberships ProjectMember[] @relation("Memberships"), sentInvites ProjectMember[] @relation("SentInvites")
```

## Data and state ownership

| State | Owner (per data-ownership.md) | This feature |
|---|---|---|
| Project metadata | Postgres | sole writer via Server Actions |
| Membership/roles | Postgres | reads (`getProjectRole`), binds `userId` (email → user) |
| Liveblocks room existence | Liveblocks | best-effort create/delete through the seam; never authoritative |
| Snapshot blob | Vercel Blob | best-effort delete through the seam |
| Cached lists | Next data cache (derived) | invalidated by `updateTag`; justified because list reads happen on every editor page render |

## API and integration contracts

All actions: file `app/editor/actions.ts` (`'use server'`), auth required, input parsed with Zod, return `ActionResult<T>`.

| Action | Input schema | Min role | Success data | Error codes (reason) | Tags updated |
|---|---|---|---|---|---|
| `createProject` | `CreateProjectInput` | signed-in | `{ id: string }` | `UNAUTHENTICATED`, `VALIDATION`, `UPSTREAM` | `projects:owned:{userId}` |
| `renameProject` | `RenameProjectInput` | owner | `{ id, name, description }` | `UNAUTHENTICATED`, `VALIDATION`, `FORBIDDEN`, `CONFLICT (PROJECT_ARCHIVED)`, `NOT_FOUND`, `UPSTREAM` | `project:{id}` |
| `archiveProject` | `ProjectIdInput` | owner | `{ id, status: 'ARCHIVED' }` | `UNAUTHENTICATED`, `VALIDATION`, `FORBIDDEN`, `UPSTREAM` | `project:{id}`, `projects:owned:{userId}` |
| `unarchiveProject` | `ProjectIdInput` | owner | `{ id, status: 'ACTIVE' }` | same | same |
| `deleteProject` | `ProjectIdInput` | owner | `{ id }` | `UNAUTHENTICATED`, `VALIDATION`, `FORBIDDEN`, `UPSTREAM` | `project:{id}`, `projects:owned:{userId}` |

Action skeleton (binding pattern for every action in the repo):

```ts
export async function renameProject(raw: unknown): Promise<ActionResult<{ id: string; name: string; description: string | null }>> {
  let ctx = { op: 'renameProject' } as { op: string; userId?: string; projectId?: string };
  try {
    const { user } = await requireUser(); ctx.userId = user.id;                      // throws AccessError('UNAUTHENTICATED') in actions (F02)
    const input = RenameProjectInput.parse(raw); ctx.projectId = input.projectId;    // ZodError → VALIDATION
    const { project } = await requireProjectRole(input.projectId, 'owner');          // AccessError → FORBIDDEN
    const data = await renameProjectCore({ user, project }, input);                 // CONFLICT on archived
    updateTag(`project:${project.id}`);
    return { ok: true, data };
  } catch (err) { return { ok: false, error: toActionError(err, ctx) }; }
}
```

Data functions (Server Components only):

```ts
export async function listMyProjects(userId: string): Promise<ProjectListItem[]> {
  'use cache'; cacheLife('minutes');
  const rows = await prisma.project.findMany({ where: { ownerId: userId, status: 'ACTIVE' }, orderBy: { updatedAt: 'desc' }, select: {...} });
  cacheTag(`projects:owned:${userId}`, ...rows.map(r => `project:${r.id}`));
  return rows.map(toListItem);
}
export async function listSharedProjects(userId: string): Promise<ProjectListItem[]>;  // where: { status: 'ACTIVE', owner: { deletedAt: null }, members: { some: { userId } } }; tags projects:shared:{userId} + project:{id}
```

What is cached and how it is invalidated: the serialised list per `userId`, for up to `minutes` (stale 5 m) unless a tag is updated. `createProject` → `projects:owned:{me}`; `rename` → `project:{id}` (every list containing it, mine and all members'); `archive/unarchive/delete` → both. F12 updates `projects:shared:{inviteeUserId}` on invite/remove. Because `updateTag` runs inside a Server Action, Next re-renders the current route in the same response (server-actions.md L34–74, checked 2026-10-22), so the sidebar reflects the change without a client refetch.

User-safe messages: `UNAUTHENTICATED` "Please sign in to continue."; `FORBIDDEN` "You don't have permission to do that."; `NOT_FOUND` "That project no longer exists."; `VALIDATION` "Please check the highlighted fields."; `CONFLICT/PROJECT_ARCHIVED` "This project is archived. Unarchive it to make changes."; `UPSTREAM` "Something went wrong. Please try again."

## Security and validation

- Threats: IDOR via guessed cuid (mitigated: `requireProjectRole` on every mutation; identical `FORBIDDEN` for missing/foreign); privilege escalation by editor (role rank check); mass-deletion by compromised session (owner-only; no bulk action); cache poisoning across users (tags/keys carry `userId`, never email; no request data inside `'use cache'`).
- Validation order per action: authenticate → parse → authorize → mutate (security-model "Trust boundaries" orders authn → authz → validate; parsing the id before `requireProjectRole` is required to validate the cuid, and parsing reveals nothing about existence).
- Rate limits: **none** on project lifecycle in M1 (security-model lists only invitations and snapshot saves). Vercel firewall covers volumetric abuse. Revisit if abuse observed.
- Logging: `toActionError` logs `UPSTREAM` with `{ op, userId, projectId, err }`; externals log warnings on every no-op/failed call.
- Secrets: `DATABASE_URL`, `DATABASE_URL_UNPOOLED` read only through `lib/env.ts`.
