# F07 — Acceptance Criteria

| ID | Given / When / Then | Verifies | Verification method (layer + how) |
|---|---|---|---|
| AC-001 | Given an editor in the workspace, when the canvas has mounted, then a `role="toolbar"` element with `aria-label="Shape palette"` contains exactly six buttons whose `aria-label`s are `Add rectangle`, `Add diamond`, `Add circle`, `Add pill`, `Add cylinder`, `Add hexagon` in that order, and hovering/focusing a button shows its tooltip text. | FR-001 | L1 Vitest + Testing Library `tests/unit/components/canvas/shape-palette.test.tsx` |
| AC-002 | Given a 1280 × 800 viewport, then the palette's bounding box is horizontally centred (|centre − 640| ≤ 2 px) and its bottom edge is 16 px above the viewport bottom; given a 700 × 800 viewport, then buttons are 36 px and the palette does not intersect the F10 control bar's box. | FR-001, EC-008 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` (two viewport sizes, `boundingBox()` assertions) |
| AC-003 | Given a palette button, when `pointerdown` (button 0) is followed by a `pointermove` of 3 px, then no ghost exists; when movement reaches 4 px, then a ghost with `data-testid="shape-drag-ghost"` and `aria-hidden="true"` exists and `setPointerCapture` was called with the pointer id; when the same sequence starts with button 2, then nothing happens. | FR-002, EC-011 | L1 Vitest `tests/unit/hooks/useShapeDrag.test.tsx` (jsdom, `setPointerCapture` mocked) |
| AC-004 | Given a drag of `hexagon` at zoom 1.5, when the pointer is at (400, 300), then the ghost's computed `transform` places its centre at (400, 300) ± 0.5 px and its size is 240 × 165 px (160 × 110 × 1.5), and `getComputedStyle(ghost).pointerEvents === 'none'`. | FR-002, FR-013 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` |
| AC-005 | Given a drag in progress, when `pointerup` occurs with `elementFromPoint` returning an element inside `.react-flow__pane`, then `onNodesChange` is called once with `[{ type: 'add', item }]` and once with a `select` change, in that order. | FR-003, FR-005 | L1 Vitest `tests/unit/hooks/useShapeDrag.test.tsx` with a mocked `useCanvasMutations` |
| AC-006 | Given a drag in progress, when (a) `pointerup` happens over the left sidebar, (b) `pointercancel` fires, (c) `Escape` is pressed, or (d) the window blurs, then the ghost is removed, `releasePointerCapture` was called, `onNodesChange` was never called, and `useCanUndo()` is unchanged. | FR-003, EC-001, EC-005 | L1 Vitest `tests/unit/hooks/useShapeDrag.test.tsx` (a–d as four cases) |
| AC-007 | Given `centredDropPosition`, when called with flow point (100, 200) and size 180 × 80, then it returns (10, 160); with size 96 × 96 it returns (52, 152). | FR-004 | L1 Vitest `tests/unit/canvas/drop-position.test.ts` |
| AC-008 | Given zoom 0.5 and 2.0 (set via `setViewport`) and a pan of (−640, 480), when a rectangle is dropped at client (500, 400), then the node's rendered bounding box centre is within 1 px of (500, 400) in both cases. **(reference bug §4)** | FR-004, EC-006 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` (`page.mouse` drag; read `.react-flow__node` `boundingBox()`) |
| AC-009 | Given `addNode('circle', { x: 10, y: 20 })`, then the emitted item deep-equals `{ id: /^circle_[0-9A-HJKMNP-TV-Z]{26}$/, type: 'canvasNode', position: { x: 10, y: 20 }, width: 96, height: 96, data: { label: '', shape: 'circle', color: 'neutral' } }` and no other keys; for each of the six shapes `width/height` equal `DEFAULT_SIZES[shape]`. | FR-005, FR-014 | L1 Vitest `tests/unit/hooks/useCanvasMutations.test.tsx` |
| AC-010 | Given users A (editor) and B (editor) in the same room, when A drops a diamond, then within 1 s B's canvas shows one `.react-flow__node` with the same `data-id`, the same `style.transform` (position) and the same `width/height`; B's own selection is unchanged. | FR-005, EC-003 | L3 Playwright `tests/e2e/canvas/07-shapes-collab.spec.ts` (two contexts) |
| AC-011 | Given an empty canvas with viewport `{ x: 123, y: −45, zoom: 1.3 }` set via `setViewport`, when the first node is dropped, then `getViewport()` still returns exactly `{ x: 123, y: −45, zoom: 1.3 }`; repeated for a second drop. **(reference bug §5)** | FR-006, EC-004 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` (read via `window.__rf` test hook exposed by F06 in test builds, or the `.react-flow__viewport` transform string) |
| AC-012 | Given focus on `Add pill` (via Tab), when `Enter` is pressed, then a pill node is created whose centre is within 1 px of the flow container's visual centre; the same for `Space` and for a plain click on `Add circle` (pointer moved < 4 px). | FR-007 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` |
| AC-013 | Given a node was just created by any path, then it has class `selected`, every other node has no `selected` class, and `document.activeElement` is the new node's `.react-flow__node` element. | FR-008 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` |
| AC-014 | Given one node of each shape with color `blue`, then: rectangle/pill/circle render no `<svg>` outline and have `border-radius` 12px / 9999px / 50 %; diamond/hexagon/cylinder render an `<svg preserveAspectRatio="none">` whose `polygon`/`ellipse` uses `fill="#10233D"`; all six render the label with `color: #52A8FF`; after setting `width: 300, height: 200` the SVG's bounding box is 300 × 200. | FR-009 | L1 Vitest `tests/unit/components/canvas/canvas-node.test.tsx` |
| AC-015 | Given a selected and an unselected rectangle, then the selected one has a 2 px `--accent-primary` border and the unselected a 1 px `--border-default` border (computed style). A human also confirms on the preview that the six shapes match ui-context "Shapes" (subtle at rest, brand on select) and records a screenshot in status.md. | FR-009 | Manual (visual) — reviewer opens `/editor/[id]` on the preview, drops all six shapes, selects one, screenshots |
| AC-016 | Given a rendered node, then exactly four `.react-flow__handle` elements exist with `data-handleid` ∈ {top, right, bottom, left}, each with the matching `.react-flow__handle-top|right|bottom|left` class and `data-handlepos`; none has `display: none` or `visibility: hidden`; all have `opacity: 0` at rest and `opacity: 1` when the node is hovered. **(reference bug §3)** | FR-010 | L1 Vitest `tests/unit/components/canvas/canvas-node.test.tsx` (structure, ids, classes, rest opacity via computed style in jsdom; the real-browser hover-opacity reading is repeated by TC-019 in the E2E spec as a regression guard, not as this AC's verification method) |
| AC-017 | Given two nodes, when a connection is dragged from each of the four handles of node 1 to the `left` handle of node 2 (4 runs), then each run creates one edge whose `sourceHandle` equals the starting handle (edge creation itself is F09; here the F06 `onConnect` must be invoked with that `sourceHandle`). **(reference bug §3)** | FR-010 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` (asserts `onConnect` payload via the F06 test hook, or edge count + `data-testid` once F09 lands) |

| AC-019 | Given 500 nodes rendered (fixture `large-500-nodes`), when one node's position changes through `onNodesChange`, then a render-count probe (`data-render-count` incremented in a test-only effect) increases only on that node. | FR-011, EC-010 | L1 Vitest `tests/unit/components/canvas/canvas-node.render-count.test.tsx` |
| AC-020 | Given user B is a viewer, when B opens the workspace, then no element with `aria-label="Shape palette"` exists, and when B's page evaluates `window.__canvasMutations.addNode('circle', {x:0,y:0})` (test hook) the result is `null` and no node appears for A. | FR-012, EC-002 | L3 Playwright `tests/e2e/canvas/07-shapes-collab.spec.ts` |
| AC-021 | Given the workspace DOM, then no ancestor of `.react-flow__pane` up to `<body>` has React `onPointerDown/Move/Up`/`onContextMenu` props that call `stopPropagation`/`preventDefault` (static assertion via a lint rule or a test that dispatches a synthetic `pointerdown` on the pane and asserts a `document`-level listener still receives it), and during a drag `document.elementFromPoint` over the pane returns an element inside `.react-flow__pane`, never the ghost. **(reference bug: parent intercepting DnD)** | FR-013 | L3 Playwright `tests/e2e/canvas/07-shapes.spec.ts` (`page.evaluate` during a drag) |
| AC-022 | Given `newNodeId('pill')` called 10 000 times in one tick, then all ids match `/^pill_[0-9A-HJKMNP-TV-Z]{26}$/` and are unique; `newEdgeId()` likewise matches `/^e_/`. | FR-014, EC-003 | L1 Vitest `tests/unit/canvas/ids.test.ts` |
