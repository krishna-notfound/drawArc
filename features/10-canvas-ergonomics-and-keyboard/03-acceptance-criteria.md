# F10 — Acceptance Criteria

| ID | Given / When / Then | Verifies | Verification method (layer + how) |
|---|---|---|---|
| AC-001 | Given an editor on macOS (`platform: 'mac'` injected), then a `role="toolbar"[aria-label="Canvas controls"]` contains buttons with `aria-label`s in order `Zoom out`, `Fit view`, `Zoom in`, `Undo`, `Redo`, a `role="separator"` between the groups, tooltips "Zoom out (−)", "Fit view (Shift+1)", "Zoom in (+)", "Undo (⌘Z)", "Redo (⌘⇧Z)"; with `platform: 'other'` the last two read "Undo (Ctrl+Z)", "Redo (Ctrl+Shift+Z)". | FR-001 | L1 Vitest `tests/unit/components/canvas/canvas-controls.test.tsx` |
| AC-002 | Given viewports 1280 × 800 and 700 × 800, then the control bar's box has `left` 16 px and `bottom` gap 16 px (wide) or 80 px (narrow), buttons are 32 × 32 px, and it never intersects the palette's box. | FR-001, FR-013 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-003 | Given zoom 1, when Zoom in is clicked, then after ≤ 300 ms `getViewport().zoom` > 1 and the change was animated (an intermediate read at 100 ms is strictly between); Zoom out returns below 1; Fit view on a 3-node canvas makes all node boxes visible with ≥ 20 % padding; `+`, `=`, `-`, `Shift+1` produce the same results. | FR-002, FR-006 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-004 | Given a fresh room (no local changes), then Undo and Redo are `disabled`, `aria-disabled="true"`, opacity 0.4; after one node is added, Undo is enabled and Redo disabled; after Undo is clicked, Redo is enabled; after reload both are disabled. | FR-003, EC-009 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-005 | Given a viewer, then the control bar contains exactly three buttons (zoom out / fit / zoom in) and no separator. | FR-003, FR-011 | L1 Vitest `tests/unit/components/canvas/canvas-controls.test.tsx` |
| AC-006 | Given `isEditableTarget`, then it returns true for `input`, `textarea`, `select`, `[contenteditable]`, `[contenteditable="true"]`, a `span` inside a `[role="dialog"]`, and false for `div`, `button`, `.react-flow__pane`, `body`, `null`; given `useKeyboardShortcuts` mounted and a `keydown Delete` dispatched on a textarea, then `onDelete` is not called. | FR-004 | L1 Vitest `tests/unit/canvas/shortcuts.test.ts` + `tests/unit/hooks/useKeyboardShortcuts.test.tsx` |
| AC-007 | Given the share dialog (or cheat-sheet) is open with a selected node, when `Delete`, `mod+z`, `+`, `?` are pressed with focus on the dialog's input and on its close button, then no node is deleted, zoom unchanged, no second dialog opens; `Escape` closes only the dialog. | FR-004, EC-001 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-008 | Given A and B with nodes X, Y (X selected) and edge E (selected) plus edge F (X→Y, unselected), when A presses `Delete`, then `onDelete` is called once with `{ nodes: [X], edges: [E] }`, and within 1 s both clients show no X, no E, no F (cascade), and Y remains; one Undo restores X, E, F. Repeated with `Backspace`. **(reference bug §2)** | FR-005 | L3 Playwright `tests/e2e/canvas/10-ergonomics-collab.spec.ts` |
| AC-009 | Given nothing selected, when `Delete` is pressed, then `onDelete` is not called and `useCanUndo()` is unchanged. | FR-005, EC-002 | L1 Vitest `tests/unit/hooks/useKeyboardShortcuts.test.tsx` |
| AC-010 | Given `matchShortcut` on platform `other`, then: `Ctrl+Z` → undo; `Ctrl+Shift+Z` and `Ctrl+Y` → redo; `+`, `=` → zoomIn; `-` → zoomOut; `Shift+Digit1` → fitView; `Escape` → clearSelection; `Ctrl+A` → selectAll; `Ctrl+D` → duplicate; `Delete`/`Backspace` → delete; `?` → cheatSheet; `Ctrl+-`, `Alt+=`, `Meta+Z` (platform other still accepts meta) → `zoomOut` is **null**, `zoomIn` is **null**, undo. On `mac`, `Meta+Z` → undo and `Ctrl+Z` → undo (both accepted). | FR-006 | L1 Vitest `tests/unit/canvas/shortcuts.test.ts` |
| AC-011 | Given a handled shortcut, then `event.defaultPrevented` is true; given an unhandled key (`k`), false; given `mod+d` as a viewer, false (not handled). | FR-006, FR-011, EC-007 | L1 Vitest `tests/unit/hooks/useKeyboardShortcuts.test.tsx` |
| AC-012 | Given a selected node focused via click, when `ArrowRight` is pressed, then the node moves 10 px (React Flow built-in) and F10's handler does not intercept it; when `Escape` is pressed with focus on the pane, then no node is selected. | FR-006 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-013 | Given `duplicateSelection([X, Y], [E: X→Y, F: X→Z])` where Z is not selected, then the result has 2 nodes with new ids matching `${shape}_…`, positions `+(20, 20)`, identical `width/height/data` (new object references), and exactly 1 edge (E′: X′→Y′) with a new `e_` id; `selected/dragging/measured/resizing` keys are absent. | FR-007 | L1 Vitest `tests/unit/canvas/duplicate.test.ts` |
| AC-014 | Given X, Y selected with edge E, when `mod+d` is pressed, then both clients show 4 nodes and 2 edges within 1 s, the two copies are the only selected elements on A, one Undo removes both copies and the copied edge, and `mod+d` with nothing selected changes nothing. | FR-007, EC-007, EC-012 | L3 Playwright `tests/e2e/canvas/10-ergonomics-collab.spec.ts` |
| AC-015 | Given 3 nodes, then: dragging on the empty pane from (50, 50) to a box partially overlapping node 1 selects node 1 only; Shift+drag likewise; `mod+click` on node 2 adds it; `mod+click` on node 2 again removes it; middle-drag and right-drag change `getViewport().x/y` without selecting; holding `Space` and left-dragging on the empty pane pans (corrected 2026-10-24, D-049: on a node it moves the node); clicking the pane clears the selection. | FR-008, EC-011 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-016 | Given a right-click on an unselected node, then a `role="menu"` opens within 8 px of the pointer with items "Duplicate ⌘D"/"Ctrl+D" and "Delete Del", the node becomes selected; on an edge → "Delete"; on the pane → "Select all", "Fit view", "Keyboard shortcuts"; `ArrowDown`+`Enter` on "Delete" deletes; `Escape` and pane click close it; given the target node is removed remotely while the menu is open, the menu closes. | FR-009, EC-013 | L1 Vitest `tests/unit/components/canvas/canvas-context-menu.test.tsx` (Radix in jsdom; remote removal via store update) |
| AC-017 | Given a right-button press at (300, 300) moved to (360, 320) and released (pan), then no menu is open and the viewport moved; given a right-click without movement, the menu opens. | FR-009, EC-006 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-018 | Given a right-click at (viewportWidth − 4, viewportHeight − 4) on the pane, then the menu's box is fully inside the viewport. | FR-009, EC-005 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
| AC-019 | Given `SHORTCUT_ROWS`, then its first ten rows (Action, Input) are string-identical to the rows of the "Interaction conventions" table parsed from `context/ui-context.md`; the dialog renders every row for an editor and, for a viewer, renders only Pan, Zoom, Fit view and Keyboard shortcuts. | FR-010, FR-011 | L1 Vitest `tests/unit/canvas/shortcuts-copy.test.ts` (reads the markdown file) + `tests/unit/components/canvas/shortcut-cheat-sheet.test.tsx` |
| AC-020 | Given the workspace, when `?` is pressed (and separately when "Keyboard shortcuts" is chosen from the pane menu), then a dialog titled "Keyboard shortcuts" opens with focus trapped inside, `Escape` closes it and focus returns to the previously focused element. | FR-010 | L3 Playwright `tests/e2e/canvas/10-ergonomics.spec.ts` |
