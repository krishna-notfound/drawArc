# drawArc — Code Standards

> PROPOSED. Binding for all implementation once the owner approves the planning package. The Next.js 16 section is derived from the docs shipped in `node_modules/next/dist/docs/` (VERIFIED 2026-10-22) and is not optional.

## General

- Small, single-purpose modules; name files after the responsibility, not the technology (`access.ts`, not `prisma-helpers.ts`).
- Fix root causes; no workaround layers.
- Respect the dependency direction in [architecture-context.md](architecture-context.md): `app → components → lib → SDKs`; `trigger → lib/types`.
- No business logic in `components/`; no React in `lib/`.
- Match the surrounding code's comment density and idiom; comments explain *why*, not *what*.
- Do not modify generated foundation files (`components/ui/*`, Prisma generated client, Clerk/Liveblocks config scaffolds) unless the task explicitly requires it.

## TypeScript

- `strict` on (already). No `any`; use `unknown` + narrowing at boundaries. `interface` for object contracts, `type` for unions/aliases.
- Exhaustive `switch` over discriminated unions with a `never` default.
- Import types with `import type`.
- Use the generated route-aware helpers: `PageProps<'/editor/[projectId]'>`, `LayoutProps<'/'>`, `RouteContext<'/api/projects/[projectId]/canvas'>`.

## Next.js 16 (Cache Components) — mandatory rules

1. **Never** await `cookies()`, `headers()`, `params`, or `searchParams` at the top level of a page or layout. Pass the promise into a child wrapped in `<Suspense>` and await it there. Violations fail the build (`blocking-prerender-runtime`).
2. **Never** export `runtime`, `dynamic`, `revalidate`, `fetchCache`, or `dynamicParams` from any segment or route handler. (Trigger.dev's `force-dynamic` advice does not apply here.)
3. `'use cache'` functions take only serialisable args and never read request data; pair every one with `cacheLife(...)` and `cacheTag(...)`. Use `'use cache: private'` for the session-reading DAL (`getCurrentUser`).
4. Client components that call `useSearchParams` are wrapped in `<Suspense>`; `usePathname`/`useParams` on dynamic routes likewise.
5. Server Actions: `'use server'` file in `app/**/actions.ts`; first line `const { user } = await requireUser()`; validate with Zod; return `ActionResult<T>`; call `updateTag` for immediate consistency; put `redirect()` after revalidation.
6. Route handlers: `export async function POST(request: NextRequest, { params }: RouteContext<...>)`; `await params`; parse body with Zod; return `NextResponse.json`. Never wrap the whole handler in `try/catch` that swallows Next's prerender bail-out — catch only around your own I/O.
7. `proxy.ts` is the only middleware file; it is Node-only and contains `clerkMiddleware()` plus the matcher. No auth decisions there.
8. Expected errors are return values (`ActionResult`, JSON error bodies). Only unexpected failures throw; `error.tsx` / `global-error.tsx` handle them.
9. `next/image` for avatars with `images.remotePatterns` for `https://img.clerk.com/**` only.
10. Read `node_modules/next/dist/docs/01-app/` before using any Next API you have not used in this repo; `AGENTS.md`'s Next block is regenerated by `next dev` — leave it.

## React and client state

- Client components only where interactivity, hooks, or real-time state require it; mark with `"use client"` at the top of the file that needs it, not on shared leaf utilities.
- Canvas state lives only in `useLiveblocksFlow`. Do not mirror `nodes`/`edges` into `useState`/Zustand. Derived data (selected ids) is computed via narrow selectors, not by filtering the full arrays in render.
- `nodeTypes`/`edgeTypes` objects are module-level constants; handlers passed to `<ReactFlow>` are `useCallback`; option objects are `useMemo`.
- Node/edge `data` updates create new objects (React Flow and Liveblocks both require it).
- Keyboard handlers ignore events whose target is `input`, `textarea`, or `[contenteditable]`.

## Validation and boundaries

- Zod schema per boundary; infer TS types from schemas (`z.infer`) so types and runtime agree.
- `lib/env.ts` (server, imports `server-only`) and `lib/env.public.ts` (`NEXT_PUBLIC_*` only) are the only readers of `process.env`.
- Liveblocks global types in `types/liveblocks.config.ts`; canvas types in `types/canvas.ts`; both are the single source for their shapes.

## Data access

- Prisma 7 with `@prisma/adapter-neon`; client generated to `lib/generated/prisma` (required `output`), singleton in `lib/prisma.ts` cached on `globalThis` in dev.
- Every query is scoped by the caller's id/email; no unscoped `findMany` on tenant data.
- Migrations: `prisma migrate dev` locally against a Neon dev branch; `prisma migrate deploy` in the Vercel build command against `DATABASE_URL_UNPOOLED`. Never `db push` outside local experiments.
- Keep Prisma to metadata; large content goes to Blob (D-009).

## Styling

- Token utilities only (see [ui-context.md](ui-context.md)); `cn()` from `lib/utils.ts` for class merging.
- React Flow stylesheet imported in `globals.css` after `@import "tailwindcss"`.
- No inline hex values outside `types/canvas.ts` (palette) and `globals.css` (tokens).

## Logging and errors

- `lib/logger.ts` only (`logger.info/warn/error(obj, msg)`); include `requestId`, `userId`, `projectId`, `runId` when known. No `console.*` in committed code except in `scripts/`.
- Error codes are a closed union in `lib/errors.ts` (`UNAUTHENTICATED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `VALIDATION` 400 — or 422 when the caller passes `{ status: 422 }` for semantic/limit violations, `CONFLICT` 409, `RATE_LIMITED` 429, `UPSTREAM` 502, `INTERNAL` 500); map to HTTP status in one helper. Non-member reads use `FORBIDDEN` with the same body as a missing project.

## Dependencies

- Add a dependency only when the feature spec lists it. Pin: `@xyflow/react` `~12.12`, all `@liveblocks/*` to one exact version, `prisma`/`@prisma/client`/`@prisma/adapter-neon` `~7.10`. Others use caret.
- `npm audit --audit-level=high` must be clean in CI; upgrades are their own tasks.
- Node ≥ 22.12 (Vitest 5 requirement); `.nvmrc` committed; `@types/node` `^22`.

## Git

- Branch per feature task (`feat/06-base-canvas-t03`), conventional commit messages, one logical change per commit, no commits that break `npm run check`.
- Do not commit `.env*`, generated Prisma client, or `.next/`.
